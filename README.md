# 运营开号与流程界面

Personal Agent 是主要入口。你通过对话完成授权、方案确认和每期沟通；界面只在集中填写、批量选择和作品预览时出现。

这是目标产品流程。仓库提供收集页面、本地保存服务，以及把非密钥资料映射到运营 Agent MCP 工具参数的示例代码。这里不包含房源视频 MCP。真实接口和自动交接能力仍需逐项落地验证，不要假定外部平台日历或发布接口已经打通。浏览器页面不会调用 MCP。

总流程：接入 MCP → 前置信息收集 → 长期运营方案确认 → 前 5 期主题确认 → 建立内容日历 → 每期制作方案确认 → 制作与质检 → 成片审核 → 交付、发布与复盘。

## 四层确认

- 长期方案确定运营方向。
- 前 5 期主题确定做什么。
- 每期制作方案确定具体怎么做。
- 成片审核确定实际交付是否符合要求。

## 完整流程

### 1. 接入 MCP｜对话

你通过 Personal Agent 完成 Topmoon 服务授权。已有工作空间和资料会直接复用，不会要你重新注册，也不会再问已知信息。这一步没有单独的界面。

### 2. 前置信息收集｜界面

用 `ops-intake.html` 一页集中收集平台、账号、密码和基本运营需求。平台不限，常见选项之外可以自行补充名称。

地区、目标和语言保持简洁，直接显示在页面上。客户、房产、内容方向和制作偏好默认折叠，标题加粗。你也可以在开放的要求栏里写下自己的说明。

提交后会自动保存，界面会提示你回到原来的对话。我会自行读取已保存的资料，不必把结果粘贴回来。

密码单独安全存储，不会进入普通档案、本地资料库、剪贴板、可见确认文本、收集列表接口、明文导出、MCP 参数、dry-run 输出或日志。公开记录最多只会带 `passwordStored: true`。若用 `file://` 打开、本地收集服务没有运行，普通档案仍可记在本机，但密码不会写入 localStorage；页面会明确告诉你这次密码没有保存。

个人信息展示不在开号时收集，留到每期执行时再问。

### 3. 提出长期运营方案｜对话

我会结合你的需求、实际取得的账号信息及必要分析，先给一版长期方案，不让你从空白开始写。方案包括长期目标、近期重点、受众、地区、内容主线、表达方式、渠道与更新节奏。事实、建议和待验证判断会分开表达。

### 4. 修改并确认长期方案｜对话

你直接说修改意见，我更新方案，直到你明确确认。确认后会保存正式版本，作为后续推荐和制作的依据，再进入前 5 期内容讨论。

### 5. 讨论并确认前 5 期主题｜对话＋轻量界面

我会按长期方案检索并核查信息源，推荐前 5 期主题，说明每期讲给谁、核心观点、开场、形式、推荐理由及必要素材。你自己的内容优先：已有选题先采用并完善，缺少的部分再推荐。

`ops-topics.html` 用于集中修改、替换、调整顺序和确认。未确认的主题会清楚标为未就绪，不会直接开做。

### 6. 自动建立内容日历｜界面展示

`ops-calendar.html` 根据已确认的主题、顺序和更新节奏，自动安排素材准备、制作、审核及预计发布节点，不需要你从空白日历手动排期。日期可以调整。必要的时间、时区或配合条件在聊天里问清。后续制作方案和实际进度变化应同步回这张日历。与外部平台日历的实时同步尚未验证，目前以本地保存为准。

### 7. 补齐本期必要信息｜对话，不用表单

我会读取本期主题和已有资料，只询问真正影响制作的缺项。若尚未明确个人信息展示偏好，会主动询问是否展示，并推荐适合本期的信息，例如姓名、经纪公司、服务地区或联系方式。需要则确认具体内容；不需要则跳过。已有且适用的授权不重复问。

### 8. 展示本期制作方案｜轻量预览＋对话

实际制作前，`ops-plan-preview.html` 会给你一份简短、具体的方案，说明：

- 讲什么：核心观点、开场和内容结构。
- 怎么做：内容形式、预计时长、画面与表达风格。
- 用什么：素材、出镜安排及个人信息展示。
- 需要配合什么：必要素材、事实确认或其他明确事项。

你可以直接提出修改，我更新后再展示。本期制作方案明确确认后，才开始实际制作。选择不展示个人信息，只省去信息补充，不跳过这次方案确认。

### 9. 制作与内部质检｜Agent 推进

我会把确认后的方案变成明确制作任务，协调制作、跟进进度、检查结果并推动返修。确需真实素材时才请你提供；素材不足会说明影响和替代方案。内部事实、表达、素材使用及渠道适配检查，不全部转交给你。

### 10. 成片审核与交付｜预览界面＋对话

`ops-review.html` 集中展示成片和发布文案。你可以确认，或提出具体修改。返修后再次交给你审核，不会重新走整套定位和选题流程。通过检查并取得必要确认后交付。

成片确认与发布授权分开。当前按约定由人完成发布，并只记录真实公开链接对应的发布结果。没有真实链接，不会记成一次成功的发布。

### 11. 复盘并推进下一轮

我会获取可用的发布记录、表现数据和你的反馈，按约定周期复盘，调整后续主题、形式和节奏。下一期重复「补齐必要信息 → 制作方案确认 → 制作 → 成片审核」。首批完成后，继续讨论下一批主题并更新日历；长期方案仍有效时不从头重做，确需调整时只重新核对受影响的内容。

## 文件

| 文件 | 说明 |
| --- | --- |
| `ops-intake.html` | 前置信息收集：平台、账号、密码和基本运营需求 |
| `ops-topics.html` | 前 5 期主题：批量修改、排序和确认 |
| `ops-calendar.html` | 内容日历：自动排期，日期可调整 |
| `ops-plan-preview.html` | 本期制作方案预览与确认 |
| `ops-review.html` | 成片与发布文案审核 |
| `ops-materials.html` | 以往的房源展示材料页，已不在主流程里 |
| `ops-story.html` | 以往的成交故事材料页，已不在主流程里 |
| `ops-bio.html` | 以往的个人或团队介绍材料页，已不在主流程里 |
| `screenshots/` | 旧版界面截图，这次没有按新流程重拍 |
| `server.js` | 本地收集服务：托管页面并保存 JSON；密码单独写入 `data/secrets/` |
| `lib/` | 解析收集结果，规划流程步骤，并生成运营 MCP 工具参数 |
| `INTEGRATION.md` | 如何运行本地服务，以及如何接到运营 MCP |

用浏览器打开这些 HTML 即可查看。要保存收集结果并单独保存密码，请看 [INTEGRATION.md](INTEGRATION.md)，运行 `npm start` 后打开 http://127.0.0.1:8787。

开号页不会把密码写入 `localStorage`。普通档案若需在本机暂存，只会保存去掉密钥后的内容。以 `file://` 分别打开时，浏览器也可能不会共享存储。预览参数（`?preview=...`）只用于对照界面，不会写入真实档案，也不会保存密码。

## 以往的材料页

`ops-materials.html`、`ops-story.html`、`ops-bio.html` 仍留在仓库里，但已不是主流程的一部分。每期缺项改在对话里补齐；只有确实需要真实素材时，才请你提供。这些页面没有按新流程重新设计。

## 接到运营 MCP

页面本身只收集和预览，不会调用 MCP。用 `npm start` 启动本地服务后，提交会把去掉密钥的 JSON 存到 `data/`，如有密码则单独写入 `data/secrets/`（目录已加入 `.gitignore`）。我会读取这些结果，再调用已连接的运营 MCP 工具。不要把密码映射进 `submit_account` 或其他工具参数。也不要发明一次成功的发布。

映射细节和 dry-run 示例见 [INTEGRATION.md](INTEGRATION.md)。本地验证：

```bash
npm test
npm run dry-run
```
