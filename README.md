# 运营开号与素材收集界面

这是开号信息收集和生产素材收集的界面，以及运营 Agent 的完整流程说明。仓库里同时提供把收集结果保存下来、并映射到运营 Agent MCP 工具参数的示例代码。这里不包含房源视频 MCP。

流程按 MCP 中的运营 Agent 对齐：界面只负责开号收集和制作材料收集；方案、选题、验收和发布确认在对话里完成；制作、排期和复盘交给运营平台。不自动公开发布，交付不等于发布。

## 完整流程

### 1. 开号接入

用第一界面收集基础信息和「想做什么」，写入用户资料库，结果由用户粘贴回对话。Agent 先查看已接入的账号，再把已核实的资料提交或补全到平台，不需要也不索要登录密码。资料齐全后，平台做账号诊断。

主要收集基础信息和「想做什么」，必填项尽量少，更细的偏好为选填。目标市场和目标人群不必在开号时锁死，可先空着，放到下一步方案里标「待验证」。

**对外展示信息**（始终可见）：姓名必填；头衔、电话、邮箱、头像选填。这些信息只用于对外展示，不是登录凭证。后续制作时可自动同步。用户可在单条内容上改展示项，但不会改这里保存的开号资料。

按钮文案是「完成收集」，不要写成「重新生成运营方案」。界面不生成运营方案。

### 2. 定位方案（对话文档）

读取平台的定位建议，整理成可审阅的运营方案给用户看：包括对账号的理解，以及需要确认的问题。用户接受、修改，或自己给出长期方向，再把决定回传平台。信息不足时标「待验证」，可编辑，不在开号时锁定。

默认每条内容仍要用户确认。如果用户允许在这个定位内自行推进，可以在确认方案时一并说明。

### 3. 选题与开始制作

方案确认后，Agent 主动询问是否开始制作。用户已经确定要做的内容，按用户的方向直接委托制作；需要建议时，先检索信息源并给出本轮推荐（讲给谁、核心答案、为什么现在做、形式和开场）。用户逐条选择接受、修改、拒绝或稍后再说；用户指定的内容优先。接受后，平台生成制作任务单和脚本。

有必须展示的内容或必须用的风格，只问一次；没有就按推荐来。

### 4. 脚本、日历和材料

制作任务出来后，读取脚本（逐段台词、拍摄清单、发布文案）和内容日历（准备、拍摄、剪辑、发布、数据上传）。如果还缺用户需要展示的材料，再回到对应收集界面。收集结果自动复制后贴回对话；若上传了文件，请把原文件和复制结果一起发回对话。这一步仍只收集，不在界面里生成文案或成片。

需要真人出镜时，拍摄由用户按清单完成。

### 5. 制作与交付

制作进度以平台状态为准：制作中、待验收、已交付待发布、已发布。成片和文案在对话里交付。制作过程中不逐段打断确认；已确认的前提和方案必须遵守。若用 AI 生成出镜，须事先说明画面不是真人。诊断、脚本或排期受阻时，向平台专家求助。

### 6. 验收与修改

用户看成片和文案后，确认交付，或说明要改哪里。修改按问题回到对应环节，不默认全盘重做。确认交付后，进入「已交付待发布」，由约定的人发布，不会自动发出去。

### 7. 发布前确认

对外发布默认每条都要用户点头：是否现在发或定时发、是否投流、是否标注 AI 生成内容。用户明确授权「以后同类内容直接发」后，同类可以不再逐条问。账号授权、付费档位和公开发布仍分别确认。

只有作品真正发出、并有对应渠道的公开链接后，才回传发布结果。交付不等于发布，没有真实链接不回传。

### 8. 发布后跟进

回传后更新日历，并询问是否开始下一条（已选列表里的，或新的推荐）。按日历上传账号数据，平台会自动复盘并调整后续内容。商单、合作报价和对外回复只起草，发出前仍要用户拍板。

### 9. 异常与停运

平台验证码、2FA、身份验证、限流或封号申诉，只能用户本人在对应平台完成。Agent 可以协助判断步骤、准备说明，但不代为提交身份材料，也不把密码写在对话里。

要停止运营并删除账号，需要用户明确同意并确认用户名；删除后 30 天内可联系平台恢复。

## 文件

| 文件 | 说明 |
| --- | --- |
| `ops-intake.html` | 第一界面：用户基础信息、想做什么，以及对外展示信息 |
| `ops-materials.html` | 素材收集：房源展示（以房源 URL 为主） |
| `ops-story.html` | 素材收集：成交故事（案例简述、链接、不限形式文件含 PDF/Word、补充信息） |
| `ops-bio.html` | 素材收集：个人或团队介绍（链接、不限形式文件含 PDF/Word、介绍文字、补充信息） |
| `screenshots/` | 界面关键状态截图，便于对照 |
| `server.js` | 本地收集服务：托管页面并保存 JSON |
| `lib/` | 解析收集结果，并生成运营 MCP 工具参数 |
| `INTEGRATION.md` | 如何运行本地服务，以及如何接到运营 MCP |

用浏览器直接打开这些 HTML 文件即可使用。若要保存收集结果并查看对接方式，请看 [INTEGRATION.md](INTEGRATION.md)，运行 `npm start` 后打开 http://127.0.0.1:8787。

开号页和素材页通过 `localStorage` 共享键 `ops-user-library` 和 `ops-display-profile`。注意：以 `file://` 分别打开时，浏览器可能不会共享存储。

完成收集后，结果会自动复制为纯文本，方便粘贴回对话。助手不会自动探测或拉取表单结果。若上传了文件，请把原文件和复制结果一起发回对话。预览参数（`?preview=...`）只用于截图，不会触发自动复制。

## 素材收集：房源展示

- 以房源 URL 为先。
- 可选择「是否展示经纪人个人信息」。
- 若选择展示：按字段勾选，并可只为这一条填写覆盖值（标记「本次更换」），不改开号资料库。
- 默认勾选：已有值的「姓名」和「电话」；「头衔」「邮箱」「头像」默认不勾。
- 至少勾选一个已有值的字段，才能完成收集。

## 素材收集：成交故事

- 可选填写标准案例表单：这笔是（帮客户买入 / 帮业主卖出 / 其他）、区域或社区、成交时间或周期、成交价格或区间、案例简述。
- 支持上传相关链接，以及不限形式的文件（图片、音频、视频、PDF、Word 等文档均可）。
- 可填写补充信息（例如要求匿名、不要露出客户正脸）。
- 至少提供一项材料（简述、链接或任意文件），或选择暂时跳过。
- 收集结果用于后续制作叙事型内容；界面本身不生成文案。

## 素材收集：个人或团队介绍

- 必选介绍对象：个人或团队。
- 支持上传相关链接，以及不限形式的文件（图片、音频、视频、PDF、Word 等文档均可），并填写介绍文字。
- 可填写补充信息。若开号资料里已有对外姓名或头衔，页面会提示，但不会改开号资料。
- 至少提供一项材料（链接、任意文件或介绍文字），或选择暂时跳过。
- 收集结果用于后续撰写专业 Bio 文案；界面本身不生成文案。

## 接到运营 MCP

页面本身只收集，不会调用 MCP。用 `npm start` 启动本地服务后，完成收集会把 JSON 存到 `data/`，并仍然自动复制纯文本。运营 Agent 读取这些结果（或用户粘贴回对话的文本），再调用已连接的运营 MCP 工具。浏览器不能直接打 MCP，也没有虚构的发布接口。

映射细节、9 步工具对照和 dry-run 示例见 [INTEGRATION.md](INTEGRATION.md)。本地验证：

```bash
npm test
npm run dry-run
```
